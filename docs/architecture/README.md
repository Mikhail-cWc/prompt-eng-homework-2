# Архитектура «Бункера»

HTML ниже — снимок версии 2.0. В промптах 2.1 увеличены
лимиты ответов и максимум времени на чтение; актуальные значения приведены в
[интерфейсе LLM](LLM_TOOLS.md) и [README проекта](../../README.md).

Автономные интерактивные страницы, созданные навыком Archify 2.17:

- [Что доступно LLM](llm-tools.html) — запрашиваемый инструмент, игровые JSON-действия и личная память. [Точный интерфейс](LLM_TOOLS.md).

- [Архитектура игры](architecture.html) — сайт, FastAPI, движок, адаптер моделей, Yandex AI Studio, SQLite/FTS5.
- [Взаимодействие на одном ходу](interaction.html) — заявки, выбор выступающего, поиск, streaming, проверка и публикация.

HTML можно открыть локально. Схемы и пояснения написаны по-русски; встроенное
меню просмотрщика и атрибут `html lang` используют английский fallback Archify.
Анимация выключена. Переключение тем, масштабирование и исследование связей
предоставляются встроенным просмотрщиком.

## Как читать

Архитектурная схема показывает логические компоненты. FastAPI, Engine, функции
правил, построение контекста, адаптер и Store работают в одном серверном процессе.
Разделение блоков не означает отдельные сетевые сервисы. Только вызовы Yandex
уходят во внешнее облако. Движок объединяет `engine.py`, `rules.py`, `context.py`;
JSON Schema/Pydantic и проверка игровых действий выполняются на сервере.

Диаграмма взаимодействия — один такт **свободной дискуссии** после обязательных
выступлений. Сначала игроки получают одинаковую публичную историю с собственными
закрытыми данными. Заявки собираются параллельно; семафор ограничивает сеть тремя
вызовами. Следующего выступающего выбирает `choose_speaker`, а не ведущий.
FTS5 исполняется только для выбранной заявки и только по документам текущего раунда.

Участник «Сервер игры» объединяет FastAPI и Engine. Стрелки streaming описывают
один фрагмент повторяющегося обмена: адаптер извлекает только корневой `text`,
сервер сохраняет техническое событие, FastAPI читает журнал и передаёт его через SSE.
Окончательный JSON проходит проверку; сначала сохраняется принятый вызов,
затем применяется действие и публикуется событие `history`. Личная заметка не
входит в публичное событие. Ошибка порождает отдельную ограниченную попытку с
обратной связью. Уже принятые действия защищены постоянным `action_key`.

После принятой речи есть 4–20 секунд на чтение. Перед следующей речью вновь
собираются заявки. При исчерпании обсуждения идут последнее слово, предварительный
бюллетень, защита всех лидеров, решающий бюллетень и одно изгнание. В решающем
бюллетене можно голосовать против любого другого оставшегося. Ничья разрешается
сохранённым seed; после трёх раундов места получают трое. Эти правила относятся
к новым партиям 2.0; старые записи 1.0 не изменяются.

Зрительский инспектор имеет доступ к секретам, но не используется для построения
контекста игроков. Архивная запись воспроизводится локально во frontend без LLM.
